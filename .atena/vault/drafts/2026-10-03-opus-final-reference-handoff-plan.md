# Plano - handoff final de referencias para Opus 5.5

## Objetivo

Converter os masters P0-P4 aprovados em um pacote de handoff preciso para a implementacao externa pelo Opus 5.5. O pacote define o que e referencia vigente, como cada familia deve ser convertida em asset de runtime e quais regras canonicas nao podem ser alteradas.

## Escopo

1. Atualizar o inventario Opus com os caminhos exatos dos masters P0-P4 vigentes.
2. Criar cinco briefs de implementacao, um para cada pacote P0-P4, com fontes, entregaveis, arquivos permitidos, nao-objetivos, aceite e validacao local.
3. Criar uma matriz de conversao: master -> atlas/familia -> pivot -> estados minimos -> cena consumidora futura.
4. Consolidar as travas obrigatorias: carroca aberta sem cavalo/quartos; calcas opacas; chao continuo; gates de teia; drows contextuais; Marcas Shar -> aranha de Lolth; Marca IX sem nona cura.
5. Criar checklist de admissao que o Opus deve cumprir antes de cada arquivo entrar no Godot.

## Nao escopo

Nao gerar sprites finais, recortar atlas, alterar o projeto Godot, instalar dependencias, chamar o Opus, publicar arquivos ou implementar sistemas.

## Aceitacao

- Cada master vigente P0-P4 tem um caminho unico e uma familia de destino proposta.
- Nenhuma referencia historica ou descartada aparece como fonte de implementacao.
- Cada brief limita o Opus a um pacote pequeno, verificavel e sem invencao de lore/mecanicas.
- A matriz inclui pivots, estados e condicoes minimas de validacao.
- O pacote deixa explicito que admissao no Godot exige plano posterior e aprovacao propria.

## Gaps

- **BLOCKING:** nenhum para documentar o handoff.
- **DEFERRED:** resolucao final de celulas, recorte de atlas, colisao, cena e teste no Godot; essas decisoes pertencem a cada pacote de integracao.

## Plano de voo

1. Inventariar os masters aprovados e suas versoes vigentes.
2. Produzir matriz e briefs P0-P4.
3. Validar links, exclusoes e regras canonicas.
4. Registrar evidencia e aguardar aprovacao humana antes de qualquer execucao externa.
